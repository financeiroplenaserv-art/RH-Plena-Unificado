## 2. ⚠️ supabase.exe bloqueado pelo Windows (Device Guard / Smart App Control)

O executável do Supabase CLI passou a ser bloqueado ("não é possível confirmar quem
publicou supabase.exe") — política do Windows, não dá para contornar pelo código.
**Fallbacks criados (usam o token do CLI lido do Gerenciador de Credenciais do
Windows, target `Supabase CLI:supabase`, nunca impresso):**

- `scripts/lib/cred-supabase.ps1` — leitura do token (dot-sourced pelos outros dois).
- `scripts/lib/executar-sql-management-api.ps1 -Query "..."` — roda SQL pela
  Management API (`POST /v1/projects/<ref>/database/query`). Substitui
  `npx supabase db query --linked`. Se mandar vários statements, a API só devolve
  o resultado do **primeiro**.
- `scripts/lib/implantar-edge-function.ps1 -Slug <slug> -Arquivo <caminho/index.ts>`
  — deploy de Edge Function pela Management API (`POST .../functions/deploy`,
  multipart com o fonte; o bundle é feito no servidor). Sai com `verify_jwt: false`
  por padrão (equivalente ao `--no-verify-jwt`). Usado 3x nesta sessão (v15→v17).

Se um dia o CLI for liberado pela TI, os comandos tradicionais voltam a valer.

## 3. Sync passa a importar SÓ checklists ativos (decisão da gestão)

- A API do PL marca o toggle "Status" da tela deles no campo numérico **`ativo`**
  (1 = ativo, 0 = inativo) — descoberto via modo de diagnóstico novo: chamar a
  function com corpo `{"debug": true}` devolve campos + distribuição de `ativo` +
  registro de exemplo na resposta HTTP.
- Filtro em `checklistAtivo()` (fail-open: sem o campo, considera ativo).
- Inativos são **removidos do espelho por id ANTES da reconciliação** — os nunca
  iniciados têm `data_inicio` NULL e o filtro de data da reconciliação não os
  alcançaria. Os QAs órfãos saem no `bi_limpar_dados_antigos()` (passo 6 do sync).
- Resultado do sync manual: 644 ativos importados, 19 inativos removidos;
