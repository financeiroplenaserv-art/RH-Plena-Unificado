## Adendo — e-mail do Supabase sobre GRANTs (30/10/2026)

A gestão recebeu o aviso do Supabase: a partir de 30/10/2026, tabelas novas
no schema `public` deixam de receber acesso automático da Data API (PostgREST/
supabase-js) — migration que cria tabela precisa de GRANT explícito no mesmo
arquivo, senão a tabela fica inalcançável ("permission denied").

Análise do impacto no CORH:

- **Tabelas existentes: nada muda, nada a fazer** (mantêm os grants atuais).
- Conferido: nossas 111 migrations só têm `GRANT EXECUTE ON FUNCTION` —
  nenhuma concede tabela, porque valia o default antigo do Supabase.
- **Regra nova registrada no AGENTS.md** (seção 8, "Migrations"): toda
  migration que criar tabela deve incluir
  `grant select, insert, update, delete on public.<tabela> to authenticated;`
  e o mesmo para `service_role` (Edge Functions). `anon` só se a tabela for
  pública de propósito (em geral não é — o app só usa `authenticated`).
- O GRANT não fura o RLS: as policies continuam valendo por cima.
